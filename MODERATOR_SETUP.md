# Локальная модерация тем

Приложение `moderator.py` показывает новые ответы из Google Таблицы. Можно
посмотреть данные заявки, увидеть увеличенное PNG-превью прямо в окне,
скопировать CSS одной кнопкой и сгенерировать файлы публикации. Файлы принимаются
из Google Drive или по публичным ссылкам общего доступа OneDrive. Подтверждение
скачивает файлы, создаёт или обновляет `themes/<id>/style.css`,
`themes/<id>/preview.png` и запись в `catalog.json`.
Изменения остаются локальными; GitHub автоматически не меняется.

## Установка

Нужен Python 3 и Windows. В PowerShell из папки проекта выполните:

```powershell
py -m pip install -r requirements-moderator.txt
Copy-Item moderator_config.example.json moderator_config.json
```

Откройте `moderator_config.json` и укажите:

- `spreadsheet_id` — часть URL Google Таблицы между `/d/` и `/edit`;
- `sheet_name` — точное название вкладки с ответами внизу таблицы.

## Доступ к Google

1. В Google Cloud Console создайте проект и включите **Google Sheets API** и
   **Google Drive API**.
2. Настройте экран согласия OAuth. Если приложение в режиме тестирования,
   добавьте свой Google-аккаунт как тестового пользователя.
3. Создайте OAuth Client ID типа **Desktop app** и скачайте JSON-файл.
4. Положите его в корень репозитория под именем `credentials.json`.
5. Запустите `py moderator.py`. При первом запуске войдите в Google-аккаунт,
   который имеет доступ к таблице и загруженным файлам формы, и подтвердите
   доступ.

Если OAuth consent screen оставлен в режиме **Testing** для внешнего приложения,
Google может потребовать повторную авторизацию примерно раз в 7 дней.

Первый запуск добавит в таблицу столбец `Статус модерации`, если его ещё нет.
Дальше приложение показывает строки, где этот столбец пустой. Кнопка
**Отклонить заявку** помечает запись статусом `Отклонено — локально` и больше
не показывает её в программе. Ответ автора в таблице не удаляется. Отклонённые
заявки дополнительно сохраняются в локальном `moderator_rejections.json`,
который исключён из Git. Чтобы снова показывать такие заявки, удалите этот файл.

## Создание темы

Нажмите заявку, проверьте данные, теги и файлы, затем нажмите
**Сгенерировать тему и добавить в каталог**. Введите ID темы — он же будет
именем папки в `themes/`, например `demo`. Используйте строчные латинские
буквы, цифры и дефисы. Описание можно оставить пустым.

Для файлов OneDrive используйте ссылки общего доступа, доступные всем, у кого
есть ссылка. Выберите заявку, чтобы увидеть PNG-превью; кнопка **Копировать CSS**
загружает CSS и помещает его в буфер обмена.
Теги из формы сохраняются отдельно: один непустой тег на каждой строке.

- Для **первого релиза** ID и папка должны быть новыми.
- Для **обновления** ID должен уже существовать в каталоге, а имя папки должно
  совпасть с папкой этой темы.
- В каталог записывается лицензия `MIT`.
- Добавьте в форму обязательное подтверждение автора, что он разрешает
  публикацию своей темы под лицензией MIT.
- Допускается не больше трёх тегов; при превышении заявка не будет добавлена.
- Файлы должны быть ровно одним `.css` и одним настоящим `.png`.

После создания файлов приложение помечает ответ как `Одобрено — локально`.
Проверьте изменения в `catalog.json` и `themes/`, затем выполните обычный commit/push,
когда будете готовы их опубликовать.

Кнопка **Git add + commit + push** вверху справа показывает последний commit,
запрашивает номер issue, показывает текущие изменения для подтверждения и
перед `git add .` обновляет `updatedAt` локальным временем с точностью до
секунды. `schemaVersion` не меняется. Затем выполняются
`git add .`, `git commit -m "#<номер>"` и `git push`. В commit попадут все
изменения в папке репозитория.

## Конфиденциальность

`credentials.json`, `token.json` и `moderator_config.json` — локальные файлы.
Не отправляйте их в репозиторий и никому не передавайте. `.gitignore` уже
исключает их из Git.
